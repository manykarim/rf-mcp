# MCP tool reference

Generated by `scripts/generate_tool_reference.py` from the schemas the server publishes; do not edit by hand.
Regenerate with `uv run python scripts/generate_tool_reference.py`.

The `rf_*` tools share these parameters (`rf_diagnose` takes only `root`):

- `root` is the project folder (with `robot.toml`); without it the server's `--root` is used.
- `profile` applies a `robot.toml` profile (`-p`).
- `target` overrides the execution mode for one call: `server` runs robotcode on the MCP host, `client` returns
  the command for the agent's own shell (see [Execution modes](CONFIGURATION.md#execution-modes)).
- `shell` picks the syntax of client-mode commands (`powershell` or `bash`).

Arguments that are empty (`""`, `[]`, `{}`, `"[]"`, `"null"`) count as not set, and list arguments also accept a
JSON array string, a Python list string or a comma-separated string.

### `rf_discover`

Use when you need the tests, tasks, suites, tags, files, metadata, profiles or config of a project - instead of grepping or reading .robot files. Returns each test's longname (use it for by_longname in rf_run/rf_debug), source:line and tags; `search` filters by text, action='tags' maps tags to tests. action='read' with paths=['robot.toml','resources/*.resource','docs/*.md'] returns several files in one call. Mistake to avoid: selecting tests by file path, or one Read per file.

Annotations: read-only.

| parameter | type | default | description |
| --- | --- | --- | --- |
| `action` | `tests` \| `tasks` \| `suites` \| `tags` \| `files` \| `metadata` \| `info` \| `all` \| `config` \| `profiles` \| `profile_show` \| `read` | `tests` | What to list: tests, tasks, suites, tags (tag -> tests), files, metadata, info, all, config, profiles, profile_show; read = the text of several project files (paths/globs) in one call. |
| `search` | string |  | Only items whose name, doc or tags contain this text. |
| `search_regex` | string |  | Only items matching this regular expression. |
| `include_tags` | list of string |  | Only tests with these tags (-i); a list such as ['smoke']. |
| `exclude_tags` | list of string |  | Skip tests with these tags (-e). |
| `by_longname` | list of string |  | Exact test/suite longnames from rf_discover, e.g. ['Tests.Login.Valid Login']. |
| `by_test_metadata` | list of string |  | Only tests with this test metadata, 'Name:Value' (-btm). |
| `exclude_by_test_metadata` | list of string |  | Skip tests with this test metadata, 'Name:Value' (-ebtm). |
| `include_values` | boolean | `true` | action='metadata': include the values. |
| `verbose` | boolean | `false` | Return robotcode's full items instead of longname/source/tags. |
| `paths` | list of string |  | Files or folders relative to root; default: the robot.toml `paths`. |

Common parameters: `root`, `profile`, `target`, `shell`.

### `rf_analyze`

Use when you wrote or edited .robot/.resource files, before any rf_run, and to check a project without running it. Runs robotcode static analysis and returns diagnostics (file, 0-based line/character, severity, code, message) plus has_errors/has_warnings; collect_unused=true finds unused keywords and variables. Mistake to avoid: running a new suite before analysis is clean - each KeywordNotFound then costs a full run.

Annotations: none.

| parameter | type | default | description |
| --- | --- | --- | --- |
| `paths` | list of string |  | Files or folders to analyze; default: the whole project. |
| `severity` | string |  | Only report this severity or worse: error, warning, info, hint. |
| `code` | string |  | Only report this diagnostic code, e.g. KeywordNotFound. |
| `filter_glob` | string |  | Glob of files to analyze, e.g. 'tests/**/*.robot'. |
| `collect_unused` | boolean | `false` | Also report unused keywords and variables. |
| `files` | object of string |  | Server mode: {relative path: content} written into the root before the call (remote runners). |

Common parameters: `root`, `profile`, `target`, `shell`.

### `rf_doc`

Use when you need a keyword's exact name, arguments or documentation - never guess them. action='keywords' lists keywords of `library` whose name matches any `pattern`; matching is by name, not meaning, so pass synonyms (['upload', 'file', 'attach']). action='keyword' shows one keyword's signature, action='lib' a library overview. Project libraries and .resource files resolve via robot.toml. Mistake to avoid: inventing keyword names from memory and finding out at run time.

Annotations: read-only.

| parameter | type | default | description |
| --- | --- | --- | --- |
| `action` | `lib` \| `keywords` \| `keyword` | `keywords` | keywords: list matching keywords; keyword: one keyword's signature and doc; lib: library overview. |
| `library` | string |  | Library name (Browser, Collections) or a .resource/.py path. |
| `pattern` | list of string |  | Keyword name or name fragments; several are matched with OR, e.g. ['upload', 'file', 'attach']. |

Common parameters: `root`, `profile`, `target`, `shell`.

### `rf_run`

Use when you need to execute tests or tasks. Select with by_longname (from rf_discover) or tags, not with a single file in `paths`: the file becomes the top suite and parent __init__.robot setups are skipped. Returns `outcome` (PASS or FAIL with counts), exit_code and `failures` ('test: message'); ask rf_results for details. Pin a full run with output='full.xml', then rerun only failures with rerunfailed. Mistake to avoid: rerunning the whole suite after fixing one test - rerun its longname.

Annotations: open world.

| parameter | type | default | description |
| --- | --- | --- | --- |
| `by_longname` | list of string |  | Exact test/suite longnames from rf_discover, e.g. ['Tests.Login.Valid Login']. |
| `include_tags` | list of string |  | Only tests with these tags (-i); a list such as ['smoke']. |
| `exclude_tags` | list of string |  | Skip tests with these tags (-e). |
| `by_test_metadata` | list of string |  | Only tests with this test metadata, 'Name:Value' (-btm). |
| `exclude_by_test_metadata` | list of string |  | Skip tests with this test metadata, 'Name:Value' (-ebtm). |
| `variables` | list of string |  | Variables 'NAME:value' (-v). |
| `rpa` | boolean | `false` | Run tasks (--rpa). |
| `wrapper` | string |  | Wrapper command (--wrapper), e.g. for a display server. |
| `outputdir` | string |  | Output directory (--outputdir). |
| `output` | string |  | Name of the result file (--output), e.g. 'full.xml' to pin a run. |
| `rerunfailed` | string |  | Rerun only the failed tests of this result file (--rerunfailed). |
| `dryrun` | boolean | `false` | Check keywords and arguments without executing (--dryrun). |
| `paths` | list of string |  | Files or folders relative to root; default: the robot.toml `paths`. |
| `files` | object of string |  | Server mode: {relative path: content} written into the root before the call (remote runners). |
| `timeout_seconds` | integer | `180` | Stop the run, with all its processes, after this many seconds. |

Common parameters: `root`, `profile`, `target`, `shell`.

### `rf_results`

Use when asked 'why did X fail?' or anything about the last run - call it first; never read or grep output.xml. 'summary'/'show' list results, 'log' shows a test's keyword log (failed_only, search, level, max_depth; extract_dir saves screenshots), 'stats' groups by tag or suite, 'diff' compares with `baseline`, 'merge' combines a pinned full run with reruns. Mistake to avoid: passing a result file anywhere but output_path.

Annotations: read-only.

| parameter | type | default | description |
| --- | --- | --- | --- |
| `action` | `summary` \| `show` \| `log` \| `stats` \| `diff` \| `merge` | `summary` | summary, show (test list), log (keyword log), stats, diff (against baseline), merge (rebot --merge). |
| `failed_only` | boolean | `false` | Only failed tests. |
| `search` | string |  | Only tests whose log contains this text (case-insensitive). |
| `search_regex` | string |  | Only tests whose log matches this regular expression. |
| `include_tags` | list of string |  | Only tests with these tags (-i); a list such as ['smoke']. |
| `exclude_tags` | list of string |  | Skip tests with these tags (-e). |
| `by_longname` | list of string |  | Exact test/suite longnames from rf_discover, e.g. ['Tests.Login.Valid Login']. |
| `by_test_metadata` | list of string |  | Only tests with this test metadata, 'Name:Value' (-btm). |
| `exclude_by_test_metadata` | list of string |  | Skip tests with this test metadata, 'Name:Value' (-ebtm). |
| `level` | string |  | action='log': lowest message level shown (trace, debug, info, warn, error, fail). |
| `max_depth` | integer |  | action='log': nesting depth of keywords shown (0 = unlimited). |
| `sort` | string |  | action='show'\|'stats': sort field, e.g. 'elapsed', 'name', 'failed'. |
| `by` | list of string |  | action='stats': group by 'tag', 'suite' and/or 'status'. |
| `top` | integer |  | action='show'\|'stats': at most N entries. |
| `message_chars` | integer |  | action='show'\|'diff': cut messages to N characters. |
| `extract_dir` | string |  | action='log': copy screenshots and other artefacts into this folder. |
| `output_path` | string |  | Result file relative to root (default: the last run's); for 'diff' the newer file; for 'merge' the file to write. |
| `baseline` | string |  | action='diff': the older result file to compare against. |
| `only` | list of string |  | action='diff': new-failures, new-passes, status-changes, added and/or removed. |
| `merge_inputs` | list of string |  | action='merge': result files, the full run first, then the reruns. |

Common parameters: `root`, `profile`, `target`, `shell`.

### `rf_repl`

Use when exploring a library, page or API, or authoring a new test, with no existing test in play. One session keeps imports and variables. A send may hold several lines: they run in order and stop at the first failure; a FOR/IF/TRY block goes in one send. Inspect with 'Get Aria Snapshot', '.kw <text>', '.doc <lib>', '.vars --user', '.imports'. 'save' writes the passing steps as a test. Mistake to avoid: Run Keywords cannot assign variables - send several lines instead.

Annotations: destructive, open world.

### `rf_debug`

Use when an existing test fails or behaves unexpectedly - debug the real test instead of rebuilding it in the REPL. start (with by_longname) pauses at the failure or a breakpoint with the real suite setup and variables, without overwriting output.xml. send runs keywords in the paused frame and debugger commands (.where, .list, .vars --user, .c). Put several lines in one send: they run in order and stop at the first failure. Mistake to avoid: one probe per send, or bare 'where'/'c' - debugger commands start with a dot.

Annotations: open world.

### `rf_diagnose`

Use when a keyword, REPL statement or run failed and the attached hints did not help, or in client mode with the output of a local robotcode run. Returns ranked recovery hints with fix examples for Browser, SeleniumLibrary, RequestsLibrary, AppiumLibrary, BuiltIn and robotcode sessions, plus project rules from .robotframework/hints.toml. Mistake to avoid: retrying the same failing call unchanged - apply the hint and change one thing.

Annotations: read-only.

| parameter | type | default | description |
| --- | --- | --- | --- |
| `error_text` | string | required | The error message or failing output. |
| `keyword` | string | `` | The failing keyword or whole statement, e.g. 'Click css=.btn'. |
| `arguments` | list of string |  | The keyword's arguments, if not part of `keyword`. |
| `libraries` | list of string |  | Imported libraries, e.g. ['Browser']. |
| `max_hints` | integer | `3` | Maximum number of hints. |

Common parameters: `root`.

## Skill resources

Skills are served as MCP resources (`skill://<name>/SKILL.md`, with reference files under `skill://<name>/references/...`). Agents that cannot read resources use these two tools:

- `list_resources`: List all available resources and resource templates.
- `read_resource`: Read a resource by its URI.

Resource templates of the built-in skills: `skill://rf-locators/{path*}`, `skill://rf-requests/{path*}`, `skill://rf-robotcode/{path*}`.
